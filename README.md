# uplift-copilot

会员增量建模和预算分配工具。它估计的是发券带来的增量，不是谁本来就会买；选人时还要受预算上限约束。

## 结果

默认模型（`t_learner`，逻辑回归）的 Qini 是 -0.0001，预算分配实测增量 2.32%。随机策略 3.37%，分组基线 3.60%。换成 `t_learner_gbm` 后 Qini 升到 0.0473，实测 4.28%。

但在 500 人规模下，各策略实测增量的 95% 置信区间都跨 0（约 ±4–5 个百分点），判断不了谁更好。可用的结论只有一个：先把每个实验组扩到 1,356 人以上，再决定要不要上模型。

## 实测（2026-10-21，`uplift run --model t_learner --budget 4000`）

```
样本 9600 · 训练 6720 / 测试 2880 · 处理组占比 50.1%
朴素读数：处理组 8.59% vs 对照组 6.89%（+1.70%）
Qini -0.0001 · AUUC 12.2861 · uplift@10% 0.26%
```

| 策略 | 人数 | 花费 | 预测增量 | 实测增量（95% CI） | 每元增量 |
|---|---|---|---|---|---|
| `segment_uplift`（分组基线） | 500 | 4000 | 54.53 | 3.60% [−2.0%, +9.0%] | 0.0136 |
| `random` | 500 | 4000 | 9.68 | 3.37% [−1.2%, +8.2%] | 0.0024 |
| `highest_predicted_conversion` | 500 | 4000 | 23.32 | 2.60% [−3.2%, +8.4%] | 0.0058 |
| `uplift_per_yuan`（模型） | 500 | 4000 | 94.36 | 2.32% [−2.5%, +6.8%] | 0.0236 |
| `uplift_threshold`（模型） | 500 | 4000 | 94.36 | 2.32% [−2.5%, +6.8%] | 0.0236 |

500 人的实测差异不足以区分这些策略，所有区间都跨 0。CI 由 1000 次 bootstrap 重采样得到（`policy.py::_observed_diff`）。

预测和实测的落差：默认逻辑回归给出的预测增量最大（94.36），实测反而最低（2.32%）。这说明模型在 top-k 上的排序是错的，不是幅度估大了这么简单。

### 样本量核算

```
每组至少 1,356 人（基线 7%，要检测 3 个点的增量，α=0.05，power=0.8）
当前每 campaign 约 600 人/组，只能检测约 4.7% 的增量
```

Qini ≈ 0 的原因就在这里：这个样本量检测不到 3 个点的增量。

## 指标

Qini 衡量整个排序的质量，预算分配只看 top-k。一个模型可以 Qini 0.3，却在前 10% 排序错乱，而前 10% 正是要投钱的地方。

所以项目同时输出三个指标：

| 指标 | 回答什么 | 局限 |
|---|---|---|
| Qini | 整体排序有多好 | 平均意义，不看 top-k |
| uplift@10% | 前 10% 的真实增量 | 只看一个 k，方差大 |
| 实测增量 | 选中的这批人，处理组减对照组 | 最终裁判 |

`highest_predicted_conversion` 按预测转化率排序，找的是最可能买的人，这批人不干预也会买。实测 2.60%，输给随机。

`segment_uplift` 只用「等级 × 线级」的历史增量排序，没有成员级参数，过拟合空间很小。在 9,600 条样本上，它的实测增量最高。

## 实现

```
src/uplift/
├── features.py   # 会员特征（严格 point-in-time，只用 campaign 前 90 天）
├── models.py     # T-learner + transformed outcome
├── metrics.py    # Qini / AUUC / uplift@k / 分桶
├── policy.py     # 预算约束选人（比值贪心 + 拉格朗日阈值）
├── power.py      # 样本量与 MDE
├── pipeline.py   # 训练 → 评估 → 分配
└── cli.py
```

四种模型：`t_learner`（逻辑回归）、`t_learner_gbm`（梯度提升）、`to_ridge`（transformed outcome + 岭回归）、`to_gbm`。

Qini 的定义有一个容易写错的地方：

```
Qini 系数 = (模型曲线面积 - 随机对角线面积) / (oracle 曲线面积 - 随机对角线面积)
```

必须减掉对角线。不减的话，即使把排序完全反过来，系数仍是正的，因为只要活动有总效果，曲线末端就在零以上。我在测试里踩过这个坑（`test_reversed_ranking_is_negative`）。

预算分配只考虑预测增量为正的会员。给负增量的人发券，等于花钱让他更不买。

## 快速开始

```bash
pip install -e ".[dev]"

```

## 评测

真实数据上 Qini≈0，可能是实现有 bug，也可能是数据没信号。为了区分这两者，测试里用已知真实增量的合成数据：

```python
# 真实 uplift = 0.30 * (x > 0) - 0.05
good = qini_coefficient(y, t, true_uplift)   # 0.24
bad  = qini_coefficient(y, t, random_score)  # ~0
neg  = qini_coefficient(y, t, -true_uplift)  # < 0
```

完美排序能到 0.24（不是 1.0，因为 oracle 排序也吃到了实现噪声），随机约 0，反向为负。指标实现是对的，真实数据的问题在信号和样本量。

## 设计取舍

用 Qini 而不是 AUC：AUC 衡量预测谁会转化，和谁因为干预才转化是两件事。一个 AUC 0.85 的模型可以完全没有增量价值。

保留一个明显会输的模型：「模型输给基线」是这个项目的核心发现，删掉模型只留基线等于把结论藏起来。

没用 X-learner / DR-learner：样本量不足时，更复杂的元学习器只会放大方差。先证明数据不够，再谈模型升级。

没接 LLM：这个问题不需要生成，只需要估计。加 LLM 只会让数字更难复现。

## 限制

- 数据为合成数据，`treated` 随机分配，无混淆；真实场景需要处理选择偏差
- 单人触达成本设为常数 8 元；真实场景应按人群/渠道分层
- 只支持二值干预（发/不发），不支持多档权益
- 单机单进程，不做分布式训练
- 结论仅适用于本数据集：换成真实业务数据，Qini 可能完全不同，届时以实测为准
